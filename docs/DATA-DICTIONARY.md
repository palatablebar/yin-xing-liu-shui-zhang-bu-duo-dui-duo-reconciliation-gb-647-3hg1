# 定义表 ledgerbank

## 数值与币种

- 金额、手续费一律 `Decimal`。**原币金额按原币量化到 0.01**，对外输出十进制字符串。
- 禁止 float 累加；合计由同一套 `Decimal` 路径复算。
- 银行侧签向金额 = 金额 × 方向（收 +1，付 −1）；签向手续费固定为负向支出。
- 币种：来源优先级为「币种列 > 金额中的币种记号 > 本位币默认」，来源记在 `currency_source`
  （`column` / `amount_symbol` / `default` / `unknown`）。
- 已登记币种为 `CNY`、`USD`、`HKD`；其余代码或认不出的币种列进隔离区 `CURRENCY_UNKNOWN`，
  绝不静默当作人民币。
- 金额列里的币种记号（`US$`、`HK$`、`¥`、`美元`、`港币`…）只用于识别币种，解析金额时剥离。
- 大整数编号（如 9007199254740993）全程按字符串保存，不过 `int()`。

## 折算

- 本位币 `CNY`，汇率定义「1 单位原币折合多少人民币」，保留 6 位小数；CNY 汇率恒为 1。
- 人民币金额 = 原币金额 × 汇率，量化到 0.01（四舍五入）。
- 汇率不进入 `run_id`：同一批原始文件换汇率仍属同一批次，结果按 result set 版本化。
- 汇率路径：显式覆盖 > 同批次当前 active 版本 > 默认表；因此普通重跑不会把已调整汇率打回默认。
- 逐组折算差异 = 组内银行签向人民币额 − 账簿签向人民币额 − (原币签向差额 × 汇率 到分)。
  该值从组 → 币种 → 批次逐层加总，且等于人民币差额与原币差额折算之差。

## 时间

- 存储与比较一律 UTC，页面按 +08:00 展示。
- 带偏移时间按其偏移换算；纯日期按 +08:00 当日 00:00 换算。
- 本地日桶是半开区间 `[日初, 次日初)`；候选日期差按本地日相差的自然日数计算。

## 键与去重

- 银行侧业务键：流水号；账簿侧业务键：凭证号。
- 同一业务键出现多条有效行：保留发生时间最早的一条，时间相同取文件行号小者，其余进隔离区。
- 业务键只用于去重与组内引用，不用金额或名称生成。

## 空值

- `null`、空串、`-`、`--`、`N/A`、`NA`、`NULL`、`NONE`、`未知` 是空值哨兵，只在一处定义。
- 金额为空值 → 隔离，原因码 `AMOUNT_SENTINEL`；手续费为空值 → 按 0 计。
- 空文件、仅表头、全空行是三种空态，分别返回 `EMPTY_FILE`、`HEADER_ONLY`、`ALL_BLANK`。

## 匹配与手续费

- 容差 0.02、窗口 3 天、子集上限 4 条；三者进入 run_id 的计算参数。
- **只在同一币种内配对**；容差按原币判断。人民币金额相同不构成匹配理由。
- 匹配金额只用金额与方向，不用手续费；手续费单独汇总在银行侧。
- 组内手续费分摊权重 = 组内银行**人民币**签向金额绝对值，尾差按最大余额法分到分，
  分摊合计必须等于组内实际手续费的人民币合计。
- 匹配差额（原币）= 银行签向原币匹配额 − 账簿签向原币匹配额，容差内允许非 0。
- 匹配差额（人民币）= 原币差额整笔折算 + 折算尾差。

## 结果版本

- `result_id` 由 `run_id + 规则版本 + 汇率摘要` 计算；同一输入同一汇率重跑命中同一版本。
- 版本状态：`active`（当前生效）、`superseded`（历史，完整保留）。
- 每批次最多一个 active；切换在一事务内「先撤旧再激活」，失败整体回滚。
- `matches` 查询只返回 active 版本的匹配组；无结果集的旧批次按默认汇率即时计算，仅供只读兼容。

## 状态

- 行状态：`valid`（参与对账）、`quarantine`（隔离，附原因码）。
- 批次状态：`partial_bank`、`partial_ledger`、`ready`、`matched`。
- 原因码表在 `app/reasons.py`，页面、CSV 与清单共用同一份名称。

## 运行清单

- `run_id` 由规则版本、两侧文件 sha256、参数共同计算，同一组输入重跑得到同一 `run_id`。
- 清单包含输入文件名、sha256、字节数、规则版本、参数、计数、耗时，以及生效结果号、版本、汇率与按币种核对。
